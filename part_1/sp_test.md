# Тест для самопроверки

## Промпт для составления теста по модулю 1

### Назначение

Промпт предназначен для генерации пяти вопросов рубежного теста по модулю 1 дисциплины «Инфраструктура баз данных для задач ИИ».

### Входные параметры

| Плейсхолдер | Содержание | Значение по умолчанию |
|---|---|---|
| `{question_format}` | Формат вопросов с вариантами ответа | закрытые, один правильный ответ |
| `{difficulty}` | Целевой уровень сложности: базовый, средний или продвинутый | продвинутый |
| `{additional_focus}` | Дополнительный акцент преподавателя; может быть пустым | — |

### Текст промпта

```text
Ты — преподаватель дисциплины «Инфраструктура баз данных для задач ИИ». Составь ровно 5 закрытых вопросов с выбором одного правильного ответа для рубежного теста по модулю 1 «Реляционные хранилища данных: язык SQL и программные расширения для управления структурированными данными».

Формат вопросов: {question_format}.
Целевой уровень сложности: {difficulty}.
Дополнительный акцент преподавателя: {additional_focus}.

Границы содержания модуля:
1. Реляционная алгебра, проектирование схемы БД, DDL, типы данных и нормальные формы.
2. DML для подготовки аналитических датасетов: фильтрация, сортировка, агрегирование, соединения, подзапросы.
3. Представления, индексы, процедуры, функции, триггеры и курсоры.
4. Транзакции, уровни изоляции, блокировки и управление полномочиями (DCL).
5. Работа реляционных БД с большими объёмами данных: планы выполнения, выбор индексов и поиск узких мест.

Требования к набору:
- сформулируй один вопрос по каждой из пяти тем;
- вопросы должны проверять понимание причинно-следственных связей и умение применять знания, а не воспроизводить определения;
- включи не менее двух вопросов с практическим контекстом проектирования, SQL-запроса, конкурентного доступа или оптимизации;
- не используй вопросы за пределами данного модуля: NoSQL, векторные БД, RAG, NLP и мультимедийные хранилища;
- не дублируй проверяемые умения и не объединяй несколько независимых вопросов в один;
- формулировки должны быть однозначными и самодостаточными; у каждого вопроса должен существовать проверяемый ответ;
- для каждого вопроса укажи ровно 4 варианта ответа: А, Б, В, Г; правильным может быть только один вариант;
- все неверные варианты должны быть правдоподобными и относиться к теме вопроса; не используй варианты «всё перечисленное», «ничего из перечисленного» и очевидно абсурдные ответы;
- распределяй правильные ответы между буквами А, Б, В, Г, не используя одну и ту же букву более двух раз.

Верни результат строго в формате:
1. Вопрос: ...
   А. ...
   Б. ...
   В. ...
   Г. ...
   Правильный ответ: [буква]. [полный текст правильного варианта]
   Проверяемая тема: ...

Повтори этот блок ровно пять раз. Не добавляй вступление, критерии оценивания или вопросы по другим модулям.
```

### Самопроверка перед использованием

- В наборе ровно пять вопросов и все пять тем модуля представлены.
- Каждый вопрос соотносится с результатом обучения: проектирование, реализация и администрирование реляционной БД.
- Вопросы допускают экспертную проверку без обращения к неуказанным источникам.

## Пример результата работы промта.

1. Какое требование соответствует второй нормальной форме (2НФ)?
-	[ ] Таблица не содержит повторяющихся групп значений.
-	[x] Каждый неключевой атрибут полностью зависит от всего составного первичного ключа.
-	[ ] Между таблицами отсутствуют внешние ключи.
-	[ ] Все запросы к таблице используют индекс.

2. Нужно вывести всех клиентов и число их заказов за последний месяц, включая клиентов без заказов. Как следует записать условие по дате при LEFT JOIN?
-	[x] В условии ON соединения с таблицей заказов.
-	[ ] В части WHERE после соединения.
-	[ ] В части HAVING до группировки.
-	[ ] Условие по дате использовать не нужно.

3.	Для какого случая B-tree-индекс обычно наиболее полезен?
-	[x] Для поиска строк по диапазону значений столбца.
-	[ ] Для хранения резервной копии таблицы.
-	[ ] Для автоматической нормализации схемы.
-	[ ] Для отмены незафиксированных транзакций.

4.	Две транзакции читают остаток товара, независимо вычисляют новое значение и затем записывают его. Как называется ситуация, когда запись второй транзакции затирает результат первой?
-	[ ] Фантомное чтение.
-	[ ] Грязное чтение.
-	[x] Потерянное обновление.
-	[ ] Неповторяющееся чтение.

5.	В плане выполнения запроса фактическое число строк сильно отличается от оценённого оптимизатором. Какое действие следует выполнить в первую очередь?
-	[ ] Удалить все индексы таблицы.
-	[x] Обновить статистику таблицы и проверить селективность условий.
-	[ ] Заменить все JOIN на подзапросы.
-	[ ] Отключить журнал транзакций.
