Теоретический Вопрос 2: При высокой конкурентной нагрузке на OLTP-таблицу с заказами наблюдаются частые deadlocks. Какой подход и причина наиболее точно объясняют типичную стратегию снижения блокировок?
-	[ ] Увеличить уровень изоляции до SERIALIZABLE и добавить больше триггеров — это предотвратит аномалии и снизит конфликты.

-	[ ] Перейти на ключ‑значение хранилище и выполнять все операции в одной большой транзакции — это гарантирует атомарность и устраняет deadlocks.
-	[ ] Отключить блокировки на уровне строк и полагаться на прикладную логику — это ускорит запись и полностью исключит deadlocks.

Практическое задание: Напишите SQL-запрос для подготовки датасета: получить топ‑10 клиентов по сумме заказов за последний квартал, включая регион, среднюю стоимость заказа и количество заказов. Исключите клиентов с аномально высокой средней стоимостью (более 3× медианы по всем клиентам). Используйте CTE и оконные функции.

Правильный ответ:
```
sql
WITH client_stats AS (
    SELECT
        c.client_id,
        c.region,
        COUNT(o.order_id) AS orders_count,
        SUM(o.amount) AS total_amount,
        AVG(o.amount) AS avg_amount
    FROM clients c
    JOIN orders o ON c.client_id = o.client_id
    WHERE o.order_date >= DATE_TRUNC('quarter', CURRENT_DATE) - INTERVAL '3 month'
      AND o.order_date < DATE_TRUNC('quarter', CURRENT_DATE)
    GROUP BY c.client_id, c.region
),
median_calc AS (
    SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY avg_amount) AS median_avg
    FROM client_stats
)
SELECT
    cs.client_id,
    cs.region,
    cs.orders_count,
    cs.total_amount,
    cs.avg_amount
FROM client_stats cs
CROSS JOIN median_calc mc
WHERE cs.avg_amount <= 3 * mc.median_avg
ORDER BY cs.total_amount DESC
LIMIT 10;
```

Проверяемая тема: DML: фильтрация, агрегация, соединения; оконные и агрегатные функции; подготовка аналитических датасетов.

Проверяемая тема: представления, транзакции, уровни изоляции; компромиссы согласованности и производительности.

Практическое задание: Опишите, как организовать хранение и обновление эмбеддингов товаров для ANN-поиска: какие хранилища использовать, как обеспечить согласованность с исходными данными, как реализовать фильтрацию по категории и цене, и как обрабатывать обновления при изменении описания товара.

Правильный ответ: Векторная БД (Milvus/Qdrant) для ANN-поиска и хранения векторов; реляционная БД для атрибутов (категория, цена, описание). Связь через product_id. При изменении описания — перегенерировать эмбеддинг, обновить вектор в векторной БД и атрибуты в реляционной. Для согласованности — CDC-поток или распределённая транзакция; для фильтрации — индексы и фильтры на уровне векторной БД. Обновления делать асинхронно с очередью задач, обеспечивая идемпотентность и версионирование векторов.

Проверяемая тема: интеграция хранилищ, векторные БД, эмбеддинги, воспроизводимость и актуальность данных.

Теоретический Вопрос 1: При проектировании схемы реляционной БД для ML-задач требуется учитывать будущие аналитические запросы и избежать частых JOIN. Какой подход и следствие наиболее соответствуют этой цели?
-	[ ] Строгая третья нормальная форма с множеством мелких таблиц — это гарантирует целостность и минимизирует дублирование.
-	[x] Частичная денормализация витрин с избыточными полями — это ускоряет аналитические запросы и снижает количество JOIN.
-	[ ] Хранение всех данных в одной широкой таблице без нормализации — это упрощает загрузку и исключает JOIN полностью.
-	[ ] Использование JSON-колонок вместо отдельных таблиц — это позволяет хранить все данные в одном месте без JOIN.

Теоретический Вопрос 2: В распределённой NoSQL-системе для AI-сервиса требуется обеспечить высокую доступность и масштабируемость. Какое свойство и компромисс чаще всего реализуются при этом?
-	[ ] Строгая консистентность (strong consistency) и синхронное кворумное подтверждение записи — это гарантирует отсутствие расхождений.
-	[x] Eventual consistency и асинхронная репликация — это повышает доступность и пропускную способность ценой возможной временной несогласованности.
-	[ ] Одноузловая архитектура с горячим резервированием — это обеспечивает максимальную согласованность и простоту управления.
-	[ ] Транзакционность на уровне документов и блокирующие чтения — это предотвращает конфликты и гарантирует корректность данных.
Проверяемая тема: требования к хранилищам для ИИ: масштабируемость, доступность; выбор и эксплуатация NoSQL-хранилища для AI-задач.

Практическое задание: Предложите схему хранения датасета для обучения NLP-модели: тексты статей, метаданные (источник, дата, автор), эмбеддинги и метки качества. Укажите типы хранилищ, ключи, индексы и способ обеспечения воспроизводимости экспериментов (версионирование данных).

Проверяемая тема: хранение текстовых корпусов для NLP, форматы JSON/Parquet, версионирование, воспроизводимость, интеграция хранилищ.
