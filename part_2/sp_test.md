# Тест для самопроверки

## Промпт для составления теста по модулю 2

### Назначение

Промпт предназначен для генерации пяти вопросов рубежного теста по модулю 2 дисциплины «Инфраструктура баз данных для задач ИИ».

### Входные параметры

| Плейсхолдер | Содержание | Значение по умолчанию |
|---|---|---|
| `{question_format}` | Формат вопросов с вариантами ответа | закрытые, один правильный ответ |
| `{difficulty}` | Целевой уровень сложности: базовый, средний или продвинутый | продвинутый |
| `{additional_focus}` | Дополнительный акцент преподавателя; может быть пустым | — |

### Текст промпта

```text
Ты — преподаватель дисциплины «Инфраструктура баз данных для задач ИИ». Составь ровно 5 закрытых вопросов с выбором одного правильного ответа для рубежного теста по модулю 2 «NoSQL-системы: модели данных, языки запросов и критерии выбора для AI-задач».

Формат вопросов: {question_format}.
Целевой уровень сложности: {difficulty}.
Дополнительный акцент преподавателя: {additional_focus}.

Границы содержания модуля:
1. Классификация NoSQL-систем и особенности документных, ключ-значение, колоночных и графовых моделей.
2. Проектирование NoSQL-систем: выбор модели, денормализация, ключи, партиционирование и индексы.
3. CRUD-операции и языки запросов распространённых NoSQL-систем.
4. Сравнение реляционных и NoSQL-решений по модели данных, согласованности, производительности и удобству разработки.
5. Выбор и эксплуатация NoSQL-хранилища для AI-задач: масштабирование, репликация, доступность, безопасность и надёжность.

Требования к набору:
- сформулируй один вопрос по каждой из пяти тем;
- проверяй умение обосновать инженерный выбор, а не только перечислить характеристики;
- включи не менее двух практических сценариев выбора или проектирования хранилища для конкретной AI-задачи;
- не выдавай отсутствие фиксированной схемы за отсутствие структуры и не представляй теорему CAP как возможность одновременно гарантировать всё;
- не используй вопросы за пределами данного модуля: SQL-оптимизация как самостоятельная тема, векторный поиск, RAG, хранение мультимедиа;
- не дублируй проверяемые умения и не объединяй несколько независимых вопросов в один;
- формулировки должны быть однозначными и самодостаточными; у каждого вопроса должен существовать проверяемый ответ;
- для каждого вопроса укажи ровно 4 варианта ответа: А, Б, В, Г; правильным может быть только один вариант;
- все неверные варианты должны быть правдоподобными и относиться к теме вопроса; не используй варианты «всё перечисленное», «ничего из перечисленного» и очевидно абсурдные ответы;
- распределяй правильные ответы между буквами А, Б, В, Г, не используя одну и ту же букву более двух раз.

Верни результат строго в формате:
1. Вопрос: ...
   А. ...
   Б. ...
   В. ...
   Г. ...
   Правильный ответ: [буква]. [полный текст правильного варианта]
   Проверяемая тема: ...

Повтори этот блок ровно пять раз. Не добавляй вступление, критерии оценивания или вопросы по другим модулям.
```

### Самопроверка перед использованием

- В наборе ровно пять вопросов и все пять тем модуля представлены.
- Каждый вопрос соотносится с результатом обучения: работа со слабоструктурированными данными и настройка выбранного хранилища.
- Вопросы не требуют знания конкретного продукта, если это не указано в самой формулировке.

## Пример результата работы промта.

1.	Какой тип NoSQL-хранилища лучше всего подходит для профилей пользователей с переменным набором атрибутов и вложенной структурой?
-	[x] Документная база данных.
-	[ ] Графовая база данных.
-	[ ] Колоночная база данных.
-	[ ] Реляционная база данных без JSON-полей.

2.	Какой компромисс обычно возникает при денормализации данных в документной NoSQL-БД?
-	[x] Чтение связанных данных упрощается, но обновление дублируемых данных усложняется.
-	[ ] Данные автоматически становятся строго согласованными во всех узлах.
-	[ ] Исчезает необходимость проектировать ключи и индексы.
-	[ ] База перестаёт поддерживать операции обновления.

3.	Какой фильтр необходим в операции массового обновления заданий со статусом queued на cancelled, чтобы не изменить задания других пользователей и статусов?
-	[ ] Фильтр только по новому статусу cancelled.
-	[x] Фильтр по идентификатору пользователя и текущему статусу queued.
-	[ ] Фильтр только по дате создания задания.
-	[ ] Фильтр не нужен, если используется updateMany.

4.	В каком случае выбор MongoDB вместо PostgreSQL наиболее обоснован?
-	[ ] Нужны сложные отчёты с большим числом соединений и строгая транзакционная согласованность.
-	[x] Данные имеют часто меняющуюся вложенную структуру, а основной сценарий — чтение и запись целых документов.
-	[ ] Все сущности имеют стабильную нормализованную схему и множество внешних ключей.
-	[ ] Требуется выполнять только SQL-запросы со стандартным синтаксисом.

5. Какова основная роль репликации в распределённом NoSQL-кластере?
-	[ ] Разделить данные на непересекающиеся части между узлами.
-	[ ] Заменить аутентификацию пользователей.
-	[ ] Исключить необходимость в резервном копировании.
-	[x] Создать копии данных на нескольких узлах для повышения доступности и отказоустойчивости.
